# Plant Care

A plant care app: **Flutter** frontend + **Laravel 11 REST API** (Sanctum). Users register, add plants,
get watering/fertilizing reminders, log care and follow weekly progress.
English by default, Arabic (RTL) ready.

```
plant-care-app/
├── backend/    Laravel API (application code + tests; the framework skeleton is generated by a script)
├── frontend/   Flutter app (lib/, test/, assets/; platform folders are generated by a script)
├── docs/       architecture, API, database schema, deployment + security checklist
├── scripts/    setup-backend.sh, setup-frontend.sh
└── docker-compose.yml
```

> **Why two setup scripts?** Laravel's `vendor/` and Flutter's `android/ ios/ web/` folders are generated
> by their tools. The scripts create them and place this repo's code on top. Nothing is overwritten the wrong way round.

## Prerequisites
PHP 8.2+ with Composer · Flutter 3.27+ · (optional) Docker.

## 1. Backend (Laravel)

```bash
./scripts/setup-backend.sh        # skeleton + Sanctum + .env + key + migrate + seed
cd backend
php artisan serve                 # http://127.0.0.1:8000
php artisan test                  # backend tests
```

Demo login (seeded, **demo data only**): `demo@plantcare.test` / `password`.
The demo user is also the only account allowed to edit shared categories (`PLANTCARE_CATEGORY_ADMINS` in `.env`).

Manual steps if you don't use the script: `composer create-project laravel/laravel`, copy this `backend/` on top,
`php artisan install:api`, copy `.env.example` to `.env`, `php artisan key:generate`, create `database/database.sqlite`,
`php artisan migrate --seed`, `php artisan storage:link`.

### Docker (MySQL)
```bash
./scripts/setup-backend.sh          # once, to generate the skeleton
cp backend/.env.example backend/.env
docker compose up --build           # API on :8000, MySQL, migrations run on start
docker compose --profile redis up   # also starts Redis (optional)
docker compose exec api php artisan db:seed
```

## 2. Frontend (Flutter)

```bash
./scripts/setup-frontend.sh
cd frontend
flutter run
```

### Pointing the app at the API
The URL is chosen automatically in development from `assets/config/app_config.json`:

| Target | URL used |
|---|---|
| Android emulator | `http://10.0.2.2:8000/api/v1` (10.0.2.2 is the emulator's alias for your computer) |
| iOS simulator | `http://127.0.0.1:8000/api/v1` |
| Flutter Web | `http://localhost:8000/api/v1` |
| **Physical device** | not automatic: run the API on your LAN IP and override (below) |

Physical device: start the API with `php artisan serve --host=0.0.0.0`, then

```bash
flutter run --dart-define=API_BASE_URL=http://192.168.1.20:8000/api/v1
```

Production build: set `production.api_base_url` in `app_config.json` (HTTPS) and build with
`--dart-define=APP_ENV=production`, or pass `API_BASE_URL` directly.
For Flutter Web, add the web origin to `CORS_ALLOWED_ORIGINS` in the backend `.env`
(in local mode any `localhost:<port>` is already allowed).

### Platform settings you must add after `flutter create`
- **Android** `android/app/src/main/AndroidManifest.xml`: `<uses-permission android:name="android.permission.INTERNET"/>`,
  `POST_NOTIFICATIONS`, and (to use plain-HTTP dev servers) `android:usesCleartextTraffic="true"` on `<application>` **for debug only**.
  Also add the scheduled-notification receivers from the
  [flutter_local_notifications setup guide](https://pub.dev/packages/flutter_local_notifications).
- **iOS** `ios/Runner/Info.plist`: `NSPhotoLibraryUsageDescription` (photo picker). Plain-HTTP dev needs an ATS exception.
- Fonts come from Google Fonts at runtime (internet needed on first launch). To work offline, bundle the font files.

## Project status — read this
This code was written without being able to run PHP, Composer or Flutter in the authoring environment.
**Nothing has been executed yet**: no migrations, seeders, `php artisan test`, `flutter analyze`, `flutter test`
or builds. Expect to fix a few small compile/analyzer issues on first run (typos, SDK-version deprecations such as
`DropdownButtonFormField.value` on Flutter 3.33+). Run the commands above and fix what they report.

Design choices worth knowing:
- Models are hand-written (no `freezed`/`json_serializable`), so no `build_runner` step is needed.
- Categories are shared; only emails in `PLANTCARE_CATEGORY_ADMINS` can create/edit/delete them. The Flutter app only lists them.
- "Today" and weekly boundaries use the server's timezone (UTC by default; set `APP_TIMEZONE`).
- Care-history screen shows the 30 most recent entries (no infinite scroll yet). There is no UI for creating custom reminders yet (the API supports it).
